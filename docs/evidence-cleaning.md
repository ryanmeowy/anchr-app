# 模型输入证据检查

## 处理入口

传统 RAG：rewrite → search → 按既有策略选证据 → 独立检查 → 程序保留通过段落 → 一次答案生成。无候选不调用检查；检查失败不调用答案模型，不允许 legacy 原文拼接。STRICT、SUMMARY、EXPLORE 共用检查。

Agent：三个资料工具先检查候选正文和文档元数据，再从保留结果构造模型消息。search_knowledge 重建 evidence，read_document 重建 segments 并保留原始分页进度。find_documents 按 matchedSegmentId 关联保留片段：正文被隔离时清空关联 ID 和 matchSnippet，文档身份与通过检查的名称仍可用于定位；保留片段的摘要从清洗后正文生成。仅名称匹配的文档不登记为回答证据。统计字段不参与文本分类。初始资源上下文只保留身份与范围；未经检查的文档名称不进入首轮模型。summarize_documents 的即时响应只有服务端任务状态，原文由异步处理器检查。

异步总结：读到的候选先分批检查，再进入 MAP/REDUCE；一批检查失败即终止本次任务，不作为可重试模型异常，也不使用该批原文。全部正文被隔离时同样终止。

清洗结果仅用于本次模型输入。源文件和 ES 保存原始资料；引用保留原 segmentId 和原文定位，引用内容与理由生成使用通过检查的文本。

## 段落判定与原文保留

检查请求使用独立 system 和 JSON user 消息，无历史和工具。检查模型复用当前 GENERATION 配置。程序按空行分隔自然段，将连续列表、表格和围栏代码作为结构块；名称等元数据独立检查。每个单元保留原始字符区间与换行，完全相同的字段可共享判定，字段路径记录来源。保留、隔离、不确定分别为 KEEP、ISOLATE、UNCERTAIN。模型只返回 ID、判定、短原因，不返回替换正文。

必须覆盖所有 ID 且不重复、不新增。返回格式不合法、调用异常、超时或覆盖不完整，整次检查不放行；Agent 多批检查中任一批失败也不放行该次工具结果。只保留 KEEP 原文，ISOLATE 和 UNCERTAIN 整段移除。混合事实和攻击但无法分开的检查单元整体隔离，不改写事实；正常代码、操作说明和攻击讨论不按敏感词直接删除。

结构 ID/游标/类型的有限字符值不送分类，其余字符串字段检查。被移除正文对应的 snippet 同步失效。安全规则放在 system；答案资料使用标准 JSON 序列化，Agent 工具资料仍是不可信参考内容，不能改变任务、取消引用或要求附加输出。

## 容量与失败规则

传统采用 5 文档、每文档 3 段、总共 10 段、24000 Unicode 字符的实际 JSON 证据区预算。检查额外包含字段映射，不能将其当作模型 token 上限保证。

每批最多 28000 个正文 Unicode 字符、128 个检查单元。传统链路保持一次检查；超过单元数时，在同一字段内优先合并相邻总长度最短的一对，长度相同时按原文顺序处理，直到满足上限。合并不切断结构块，审计保留各原始段落区间（Java UTF-16 起止偏移，左闭右开）。独立字段过多无法合并时返回容量失败。

预检对实际序列化的 system/user 消息计数，上限为 48000 Unicode 字符，并记录 8192 token 输出预留。字符限制是应用容量保护，不代表模型窗口保证；需对当前模型完整请求做容量验收。Agent 工具可分批，整个结果全部通过才放行；异步按约 20000 Java 字符形成外层批次。

容量失败使用 `evidence_check_capacity_exceeded`，提示缩小资料范围；异步对应 `EVIDENCE_CHECK_CAPACITY_EXCEEDED`。它与攻击判定、格式错误和调用失败分别记录。

失败展示：**本次资料未通过证据检查，无法生成可靠回答。** Agent 有此前已检查证据时可继续使用这些证据；没有时返回 GENERATION_FAILED，不通过异常触发传统降级。异步失败码 EVIDENCE_CHECK_FAILED 为永久失败。检查成功不等于事实必然正确，更不保证识别所有攻击。

## 内部审计

传统报告位于 retrieval trace.evidenceCheck；Agent 工具报告位于 step 输出摘要，异步为 EVIDENCE_CHECK_N 阶段。记录输入/清洗后 SHA-256 指纹、段落指纹及字段映射、判定及原因、数量、调用数、失败类型、模型名称、token 用量和耗时。检查报告使用内部 `EvidenceCheckReport` 类型，工具数量使用 `EvidenceStatistics`，在 Trace 边界序列化。`originalEvidenceCount` 为原始候选数，`evidenceCount` 为保留并登记的证据数，`segmentCount` 为最终模型消息中出现的不同片段数（包括压缩后的数量），`documentCount` 为返回文档条目数；实际引用数在答案完成后记录。原始工具统计不能覆盖这些结果。

异步每批先进入 EVIDENCE_CHECK_N 并记录 RUNNING，按该阶段显式记录实际模型调用次数、token 和耗时，再完成或失败。Run 用量仅累计一次；阶段切换保留检查报告和已完成的耗时，失败或取消阶段不能被改成完成。历史缺失的新字段保持未知。常规日志不打印原文、完整提示词或完整模型响应；检查报告作为内部审计数据保存。

## 验收与复跑

固定流程测试覆盖格式错误、漏 ID、重复/伪造 ID、不确定段落、混合字段、原文保持、超限和多批失败、snippet 恢复阻断、Agent 输入和证据登记、无证据终止、传统 legacy 阻断和异步失败阻断。

`src/test/java/com/anchr/core/conversation/application/impl/EvidenceCleaningLiveEvaluation.java` 为手动真实模型入口，不被 Surefire 自动运行。先编译测试类并准备 Maven 测试 classpath，再运行该类，参数为 `.env` 路径、JSONL 输出路径、重复次数（默认 20）。它只读启用的 GENERATION 配置，复用其模型与 extra_config；不启动 Spring、不写业务库。会调用收费模型。连接失败明确输出 LIVE_EVAL_BLOCKED，不能当作完成验收。

样例包括原有五类固定资料，以及攻击分段对照、129 行文字、列表/表格/代码块和超过 128 段的合并输入。旧样例保持原文不变，连续事实和攻击处于同一自然段时可能整体隔离，这种结果计为生成失败，不能算正确回答。每项 20 次，输出完整测试答案、检查报告、生成失败、标记检查与耗时。标记检查只是辅助，需逐条评审事实，尤其不能把拒答/生成失败算成正确回答。固定证据不代替线上检索联调或所有攻击类型的覆盖。

### 当前版本验收状态（2026-09-09）

程序回归 348 个测试：331 个通过、17 个条件跳过、0 个失败，涵盖工具关联摘要清理、模型输入/登记/统计一致性、结构单元与合并映射、多批异步阶段和报告保存。真实模型复跑暂被配置库连接阻塞：本地 .env 指向 127.0.0.1:3306，读取返回 CommunicationsException。新组织方式的回答质量、误删比例和完整请求容量尚未完成验收，下面历史结果不作为当前版本通过依据。
