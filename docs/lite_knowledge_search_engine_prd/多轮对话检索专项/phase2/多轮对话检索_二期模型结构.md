# 多轮对话检索专项（二期）模型结构

更新时间：2026-05-03  
状态：Draft for Execution  
依据：`多轮对话检索_二期PRD.md`

## 1. 模型设计原则

1. `resultCards` 是展示层协议：一张卡片对应一个 asset。
2. `primaryHit` 是定位层协议：每张卡片必须包含一个 segment 级主命中。
3. `additionalHits` 用于承载同一 asset 下的其他命中，不额外占用 Top3 卡片位。
4. `resultCards` 必须随 turn 持久化到 `ConversationTurn.resultCardsJson`。
5. 历史回放直接读取 `resultCardsJson`，禁止二次检索。
6. `retrievalTraceJson` 只用于开发者调试和审计，不作为历史卡片重建的唯一数据源。
7. `ConversationSession.userId` 作为未来 SSO 用户隔离的兼容口；当前无 SSO 时使用轻量 user key。

## 2. 领域模型

### 2.1 ConversationSession

用途：会话聚合根，支撑左侧历史列表。

```java
public class ConversationSession {
    private String sessionId;
    private String userId;
    private String title;
    private ConversationSessionStatus status;
    private long createdAt;
    private long updatedAt;
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sessionId` | string | 是 | 会话 ID |
| `userId` | string | 否 | 用户 ID；无 SSO 时使用 `default`、`anonymous` 或 token hash |
| `title` | string | 是 | 会话标题 |
| `status` | enum | 是 | `ACTIVE/DELETED/ARCHIVED` 等 |
| `createdAt` | long | 是 | 创建时间，毫秒时间戳 |
| `updatedAt` | long | 是 | 更新时间，毫秒时间戳 |

说明：
1. 二期不引入新的 DB 表，优先沿用 Redis。
2. `userId` 必须预留，避免未来接 SSO 时重构 session 模型。
3. 会话历史只承诺 TTL 内恢复。

## 4. Result Card 模型

### 4.1 ResultCardDTO

用途：Top3 结果卡片，一张卡片对应一个 asset。

```java
public class ResultCardDTO {
    private String assetId;
    private String assetType;
    private String fileName;
    private String title;
    private Double score;
    private Integer hitCount;
    private ResultHitDTO primaryHit;
    private List<ResultHitDTO> additionalHits;
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `assetId` | string | 是 | asset ID |
| `assetType` | enum/string | 是 | `PDF/TXT/MD/IMAGE` 或底层资产类型 |
| `fileName` | string | 否 | 文件名 |
| `title` | string | 否 | 展示标题，优先文件标题/文件名 |
| `score` | double | 否 | asset 卡片分数，默认取 `primaryHit.score` |
| `hitCount` | integer | 是 | 当前 asset 下命中数量 |
| `primaryHit` | object | 是 | 主命中 segment |
| `additionalHits` | array | 否 | 同 asset 下其他命中 |

约束：
1. `primaryHit` 必须存在。
2. `primaryHit.segmentId` 是预览定位入口。
3. 同一 asset 的多个 segment 不额外占用 Top3 卡片位。
4. `additionalHits` 可为空数组。

### 4.3 ResultCards 生成规则

输入：当轮 `retrievalResult.topCandidates`。

步骤：
1. 按候选分数排序。
2. 按 `assetId` 聚合。
3. 每个 asset 选择最高分 segment 作为 `primaryHit`。
4. 同 asset 其他高分 segment 进入 `additionalHits`。
5. 取 Top3 assets 生成 `resultCards`。
6. 序列化写入 `ConversationTurn.resultCardsJson`。
7. 卡片分数固定取 `primaryHit.score`，本期不做同 asset 多命中加权。
8. `additionalHits` 默认最多保留 2 条。

禁止：
1. 为生成卡片发起二次检索。
2. 为历史回放发起二次检索。
3. 用 `retrievalTraceJson` 作为卡片重建唯一数据源。

### 5.2 PreviewAnchorDTO

```java
public class PreviewAnchorDTO {
    private Integer pageNo;
    private Integer chunkOrder;
    private BboxDTO bbox;
    private Integer imageWidth;
    private Integer imageHeight;
}

public class BboxDTO {
    private Integer x;
    private Integer y;
    private Integer width;
    private Integer height;
    private String unit;
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pageNo` | integer | 否 | PDF 页码 |
| `chunkOrder` | integer | 否 | TXT/MD chunk 序号 |
| `bbox` | object | 否 | 图片或 OCR 命中框，结构为 `x/y/width/height/unit` |
| `bbox.x` | integer | 否 | 命中框左上角 x 坐标 |
| `bbox.y` | integer | 否 | 命中框左上角 y 坐标 |
| `bbox.width` | integer | 否 | 命中框宽度 |
| `bbox.height` | integer | 否 | 命中框高度 |
| `bbox.unit` | string | 否 | 坐标单位，当前固定为 `PIXEL` |
| `imageWidth` | integer | 否 | 原图宽度，用于 bbox 比例映射 |
| `imageHeight` | integer | 否 | 原图高度，用于 bbox 比例映射 |

说明：
1. 图片预览主路径依赖有效 bbox 绘制命中框。
2. bbox 使用原图像素坐标，前端按 `imageWidth/imageHeight` 映射到渲染尺寸。
3. bbox 缺失、越界或图片尺寸异常时，前端展示原图和命中文本，不画错框。

### 5.3 SurroundingChunkDTO

```java
public class SurroundingChunkDTO {
    private String segmentId;
    private Integer chunkOrder;
    private Integer pageNo;
    private String content;
    private String relation;
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `segmentId` | string | 是 | chunk 对应 segment ID |
| `chunkOrder` | integer | 否 | chunk 顺序 |
| `pageNo` | integer | 否 | 页码 |
| `content` | string | 是 | chunk 内容，需截断 |
| `relation` | enum/string | 是 | `previous/current/next` |

约束：
1. 默认返回 `previous/current/next`，最多 3 条。
2. 默认 `window=1`。
3. 单条 `content` 限制 2KB-4KB。
4. 无相邻 chunk 时仅返回 `current`。
5. 无权限访问时不返回内容。

## 8. Preview Cache 模型

### 8.1 PreviewCacheEntry

```java
public class PreviewCacheEntry {
    private String segmentId;
    private String tokenHash;
    private PreviewSegmentDTO preview;
    private long expiresAt;
    private long createdAt;
}
```

缓存 key：

```text
preview:segment:{segmentId}:token:{tokenHash}
```

TTL：

```text
previewUrlRemainingTtl - 30s
```

要求：
1. `tokenHash` 不可逆。
2. 不缓存原始 token。
3. 不在日志中打印完整 `previewUrl`。
4. URL 临近过期时重新签发。

## 9. Redis Key 建议

### 9.1 会话

```text
conversation:session:{sessionId}
conversation:turn:{sessionId}:{turnId}
conversation:turn:index:{sessionId}
conversation:session:index:{userId}
```

说明：
1. `conversation:session:index:{userId}` 使用 zset，score 为 `updatedAt`。
2. 会话和 turn 保持相同或兼容 TTL。
3. `expiresAt` 可由 Redis TTL 推导或保存到 session DTO。

### 9.2 预览缓存

```text
preview:segment:{segmentId}:token:{tokenHash}
```

说明：
1. 用于签名 URL 去重复用。
2. TTL 必须短于 `previewUrl` 实际有效期。

## 11. 兼容策略

1. 老 turn 没有 `resultCardsJson`：返回空 `resultCards`，不报错。
2. 老 session 没有 `userId`：读取时补默认 user key，写回可选。
3. 老 segment 没有 `chunkOrder`：`surroundingChunks` 仅返回 current。
4. 图片没有 bbox：展示原图和命中文本，不画框。
5. 预览 URL 已过期：前端自动刷新一次；仍失败则提示用户。
