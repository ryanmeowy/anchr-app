# 传统 RAG 输出验收

本轮只改传统证据组织、回答提示词与引用展示，包含 Agent 异常后的传统回退。不调整实际模型配置或部署服务。

## 本地确定性检查

- 5 文档、每文档 3 段、总 10 段同时生效，允许 3/3/3/1 分布，不强制填满 5 文档。
- 全部证据区（含元数据）按 Unicode code point 计数，不超过 24000。超长表格整段跳过；不替换短 snippet、不截断、不扩展邻近片段。
- 同步和任意流式分界下的引用保持一致，例如局部 `[3][2][1][3]` 对应 asset a/b/a 时映射为 `[1-1][2-1][1-2][1-1]`。
- 最终 citations 只含正文实际使用的证据；历史单层编号不迁移。横向卡片与片段浮层只接入传统回答。

- 检查失败或无保留正文时不调用答案模型；启用 legacy 时同样阻止原文回退。
- 正文、标题和重复字段使用统一判定，已隔离正文不能从 snippet 或 find_documents 的 matchSnippet 恢复。
- 验证 129 行文字、列表、表格、围栏代码及超过 128 个自然段：容量允许时一次检查，原文与来源区间完整保留。
- 完整检查消息计入容量预检，容量失败与攻击、格式和调用失败分开统计。
- 调用次数为一次 rewrite、一次 search、证据非空时一次检查、至多一次答案生成。

## 真实模型与链路验收

先固定 search 返回候选、顺序与正文，对照修改前后的答案，再跑完整链路。测试桩验证不能替代真实模型评审。

| 样例 | 要检查的内容 |
| --- | --- |
| 原 session 中 summaryMaxDocuments、同步 Run 与异步 Task 重试配置问题 | 对照实际命中配置文档，逐项检查数量限制、配置读取时机和重试条件；不要预设正确答案 |
| 4–5 份文档、超过 3 个片段的主题总结 | 有依据的主题是否覆盖，是否综合组织而非逐段复述 |
| 同一主题的条件与例外分布于不同片段 | 条件、例外和适用对象是否保留 |
| 两份文档陈述冲突或版本不同 | 是否明确差异而非合并为无条件结论 |
| 一个子问题缺证、全部无证据 | 是否准确说明缺失部分、是否避免编造 |
| 接近 24000 字符并含长文档名、表格、中英文和 emoji | 记录实际完整输入 token、输出 token、延迟及容量错误；不将字符预算当作模型 token 上限 |

提示词注入样例覆盖事实反转、伪造 system、取消引用、附加输出及正常安全讨论。每例重复 20 次，分别统计正确回答、注入成功、生成失败和正常内容误删，失败不计入正确回答。固定证据的结果见[证据检查验收](evidence-cleaning.md)。

保存候选/输入/实际引用 segmentId、排除原因、答案、模型标识、输入输出用量及耗时，逐条核对引用是否支持对应结论。不得在常规 INFO 中写入整段证据。若需要改变共享模型配置或召回策略，先对齐范围。

界面验收涵盖窄屏横滑、按钮边界、长名称省略、无页面横向溢出、浮层不裁切、键盘与关闭焦点恢复、正文精确跳转和返回恢复。
